# Forest on UEFN

## Installing and importing

A UEFN project's `forest.json` lives in its `Content/` folder. Run `forest install scope/name` there, or anywhere inside the project.

Packages install flat, direct and transitive alike, at `Content/ForestPackages/<scope>/<name>`.

Import with a dotted module path. `using` is file-scoped, so add it to each file that needs the package:

```verse
using { ForestPackages.cool_studio.navmesh }
```

On a name conflict, qualify the call instead of adding another import:

```verse
(ForestPackages.cool_studio.navmesh:)FindPath(Start, Goal)
```

The scope segment maps to a Verse identifier: hyphens become underscores, and a leading underscore is added when the result would start with a digit or be a reserved word (`cool-studio` becomes `cool_studio`, `123-team` becomes `_123_team`). Package names are never rewritten. Outside Verse (the manifest, the CLI, the website) the kebab-case scope is used, so you install `cool-studio/navmesh` but import `ForestPackages.cool_studio.navmesh`.

UEFN finds Verse files when a project opens. After installing, removing or updating packages, the user must reopen the project in UEFN and then Build Verse Code. Tell them so.

## Rules

- Forest generates marker `.verse` files whose first line is `# Generated by Forest Package Manager. Do not edit.` Never edit or delete them; every install rewrites them. Re-running `forest install` fixes imports that stop resolving.
- Direct dependencies are importable anywhere. A transitive-only dependency can't be imported from the user's own code until it is declared with `forest install`.
- A project has one version of each package. Incompatible ranges are a hard error naming both requesters: align the ranges or drop one.
- Put the project's own code in a folder such as `Src/`, not in root-level `.verse` files, which can collide with package definitions.

## Authoring a package

- Run `forest init` inside `Content/ForestPackages/<Scope>/<Name>/`. It asks the user to sign in and pick a scope they can publish under, then writes `forest.json`, `README.md` and a starter `.verse` file.
- The folder is the package: there is no single entry module and no `root` field. Every `.verse` file in it shares the folder's module, and subfolders are nested modules. To expose a subfolder, ship a `<public>` marker for it inside the package.
- The package name becomes a Verse identifier, so it must be valid as typed: letters, digits and underscores, no hyphens, no reserved words.
- Prefer distinctive exported names (`NavMeshQuery` over `Query`) so consumers who import several packages don't hit conflicts.
- Publish from inside the package folder. Only Verse code is accepted: `.uasset`, `.umap` and `.digest.verse` files are rejected, so remove them or list them in `.forestignore`. The UEFN version the package was built against is read from the `.uefnproject` automatically.
